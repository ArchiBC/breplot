# cetz-nurbs 性能测试（2026-09-24）

当前规模的教材插图性能可接受；千段级路径和 512 点内插已进入秒级，不宜视为无延迟交互。此结论基于下列本机测量，不包含三维遮挡或交点断线功能。

## 测试条件

- Windows 11 Pro；AMD RYZEN AI MAX+ 395，16 核／32 线程，约 95.6 GiB 可见内存。
- Typst 0.15.1；CeTZ 0.5.2；当前 release WASM，大小 193,458 字节。
- 每个用例预运行一次，再启动 5 个独立 Typst 进程编译 PDF，报告墙钟时间中位数和范围。全部 34 个用例通过，无失败或超时。
- 字体及 CeTZ 已在本机缓存；不计网络下载。独立进程无跨进程 Typst 编译缓存，但文件系统缓存已预热。未测 Tinymist 增量预览延迟。
- 峰值内存取 5 次进程 PeakWorkingSetSize 最大值；这是工作集，不等于总虚拟内存。
- 采用 x∈[0,10] 的正弦控制多边形；有理权重为 1+0.6 sin(1.7i)。多曲线用例改变形状，避免相同输入被重复调用缓存掩盖。容差为模型单位。
- `eval` 用例执行 WASM 构造／曲线转换、JSON 传输及 Typst 求值，只输出段数；`draw` 另执行实际 CeTZ 绘图。均包含进程启动和 PDF 输出，不能把 eval 总耗时称为纯几何算法耗时。
- 本机未隔离其他系统负载，结果用于工程判断；不同次数用例的控制点和节点分布不等价，不据此推断次数越高越快。

## 分析

1. 当前文章完整编译中位数为 0.662 s；1–10 条普通插图曲线约为 0.28–0.52 s，适合文档编写。该范围是本组样本的测量，不是对任意曲线的上界。
2. 同一画布 100 条曲线共输出 2,900 段，耗时 2.751 s、峰值约 322 MiB；改用独立画布没有数量级差异。大批量图元处理已影响预览响应。
3. 1024 控制点产生 1,021 段。仅生成结果耗时 0.257 s，绘制后为 2.024 s；差异表明 CeTZ 图元处理与输出在该例中占主要开销。没有使用 profiler，不能进一步精确分摊到内部函数。
4. 32 控制点的三次有理曲线，容差从 1e-2 降至 1e-6，段数由 39 增至 361，完整绘制从 0.315 s 增至 0.500 s。高曲率、极端权重或更多振荡的输入可能需要更多细分，当前样本不构成最坏情况。
5. 开放内插从 128、256 到 512 点，总耗时约为 0.265、0.426、1.702 s。当前 `construct.rs::solve` 使用稠密 Gauss–Jordan 消元，时间复杂度 O(N³)、存储 O(N²)，未利用 B 样条配点矩阵的带状结构。若要优化大规模内插，应优先考虑带状／循环带状求解。
6. 原生 release 基准将转换输入准备放在计时之外，每次重复至少 100 ms，共 5 组，并用 black_box 保留计算。它排除 WASM 解释执行、JSON、Typst 和绘图开销，不能代替插件链路数据。32 控制点三次转换约 20 μs，1024 控制点约 0.68 ms；512 点内插约 52–61 ms。

## CeTZ 三维交叉线遮蔽

核查本机 CeTZ 0.5.2 的 `src/draw/projection.typ` 与 `src/intersection.typ`：`ortho(sorted: true)` 按整条 drawable 的最大 z 排序；二维 `path-path` 返回交点，不执行交点处的深度比较或后线裁切。因此，自动后线留隙须增加相机空间交点参数求解、深度判断和局部曲线裁切。当前性能测试未包含这一尚未实现的功能。
官方接口：[ortho](https://cetz-package.github.io/docs/api/draw-functions/projections/ortho/)。

## 复现

在仓库根目录执行：

```powershell
python cetz-nurbs/benchmarks/run.py
python cetz-nurbs/benchmarks/run.py --case shared100
cargo run --release --manifest-path cetz-nurbs/rust/Cargo.toml --example benchmark
```

需要可用的 Rust、Typst 和 Python。脚本生成文件位于 `cetz-nurbs/target/benchmark/`；本次原始数据保存在同目录报告旁的 `results-2026-09-24.json`。
